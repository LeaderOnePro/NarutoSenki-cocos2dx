## 2. 前置条件(需用户动手,二者缺一不可)

### 2.1 补回安卓预编译库(38M)— 重新下载 2.2.6
- 下载 cocos2d-x 2.2.6 完整框架(官方下载源已死,用 **Internet Archive 镜像**:`https://archive.org/details/cocos2dx226`)。
- 从解压包里取出整个目录 `cocos2dx/platform/third_party/android/`,放到本仓库**同名路径**下。
- 校验:`ls cocos2dx/platform/third_party/android/prebuilt/` 应含 `libpng / libjpeg / libtiff / libwebp`(以及 `libcurl`,我们不用)。
- 这 38M **暂不纳入 git**(沿用原策略,本地放置即可);若日后要让安卓构建可复现,再在 `.gitignore` 局部放行 `!/cocos2dx/platform/third_party/android/`。

### 2.2 安卓工具链(Mac)
| 组件 | 版本/来源 | 备注 |
|---|---|---|
| JDK | 17(`brew install --cask temurin@17`) | 现机 `java` 是桩,必装 |
| Android SDK + 命令行工具 | `brew install --cask android-commandlinetools` | 装 `platform-tools`(已有 adb)、`platforms;android-XX`、`build-tools` |
| **NDK r10e** | `https://dl.google.com/android/repository/android-ndk-r10e-darwin-x86_64.zip` | 2.2.6 的标准搭档;x86_64 二进制,**Apple Silicon 需 Rosetta 2**(`softwareupdate --install-rosetta`) |
| (备选 NDK)r17c | 最后一个含 gnustl 的版本 | 若 r10e 在新版 macOS/Apple Silicon 上工具异常,改用 r17c(clang + gnustl_static 仍可编) |

> 环境变量:`export ANDROID_HOME=...`、`export NDK_ROOT=.../android-ndk-r10e`。

## 3. 构建策略:混合式(推荐)

cocos2d-x 2.2.6 原生的安卓构建是 **Eclipse + Ant**(`build.xml`/`.classpath`/`.project`),这套 2026 年已死(JDK17 跑不动老 ant、Eclipse ADT 绝迹)。两条打包路:

- **❌ 纯原版(Ant)**:复活 Eclipse/Ant 工具链,劝退。
- **✅ 混合式(推荐)**:
  - **Native 用老 NDK 编**:`ndk-build` + 仓库现成 `.mk` 文件 → 产出 `libnarutosenki.so`(armeabi-v7a)。
  - **打包用现代 Gradle**:建一个**精简 Gradle app 模块**,把上一步的 `.so` 放进 `jniLibs/armeabi-v7a/`、把 `cocos2dx/platform/android/java` 的 Java 源(`Cocos2dxActivity` 等)纳入、把 `Resources/` 拷进 `assets/`。用现代 Gradle/AGP 打 APK,`minSdk` 设低(如 19)、`compileSdk` 用新。
  - 好处:native 用老 NDK 保证 2.2.6 能编,打包用现代链保证能在 2026 的机器上出 APK、能 `adb install`。

## 4. 详细步骤(分阶段,每阶段有验证门)

### 阶段 0 — 环境就绪(用户)
完成 §2.1 + §2.2。验证门:`ndk-build --version` 可运行;`adb devices` 能看到你的安卓机;`third_party/android/prebuilt/` 四个图片库在位。

### 阶段 1 — 先编通框架 + HelloCpp(验证工具链)
- 不碰游戏,先 `cd samples/Cpp/HelloCpp/proj.android` 用老 NDK `ndk-build` 编一遍。
- **验证门**:HelloCpp 的 native `.so` 编出来 → 证明老 NDK + 框架 `.mk` + 预编译库这条链是通的。这是排错隔离点(把"框架能否编"与"游戏能否编"分开)。

### 阶段 2 — 建游戏 proj.android 脚手架(我来做,不需环境)
照搬 HelloCpp 模板,为游戏新建:
- `projects/NarutoSenki/proj.android/jni/Android.mk` — `LOCAL_SRC_FILES` 列全 **27 个 Classes .cpp + `MyUtils/sqlite3.c`** + JNI 入口;`LOCAL_WHOLE_STATIC_LIBRARIES := cocos2dx_static cocosdenshion_static box2d_static chipmunk_static`(**不含 curl/websockets**);`LOCAL_C_INCLUDES` 对齐 win32 的包含目录;`CC_ENABLE_CHIPMUNK_INTEGRATION=1`。
- `jni/Application.mk` — `APP_STL := gnustl_static`、`APP_ABI := armeabi-v7a`、`APP_CPPFLAGS += -frtti`。
- `jni/hellocpp/main.cpp`(JNI 入口,改包名)。
- `AndroidManifest.xml`(包名如 `com.narutosenki`,横屏、全屏、`glEsVersion 0x20000`)。
- Gradle app 模块(`build.gradle` / `settings.gradle` / `AndroidManifest`),`jniLibs` + `assets` 指向上述产物与 `Resources/`。
- 把 `Resources/`(52M)拷进 `assets/`(打包时;不进 git)。

### 阶段 3 — 砍网络模块,让 extensions 不依赖 curl
- 游戏 Android.mk **不编 `NetworkLayer.cpp`**;并确认 `extensions` 的 `Android.mk` 在本项目实际链接路径上**不强拉 `cocos_curl_static`**(必要时做一个不含 `network/` 的 extensions 构建变体,或 stub 掉对 HttpClient 的符号引用)。
- **验证门**:`ndk-build` 编游戏 native 通过,无 curl 相关符号缺失。

### 阶段 4 — 复核安卓条件编译分支
安卓构建会激活以前在 PC 上被绕过的安卓分支,逐一复核**不与本分支的 PC 体验恢复改动冲突**:
- `LoadLayer.h / GameOver.h / GameLayer.h` 的 `CC_PLATFORM_ANDROID` 分支。
- 四处 `setKeypadEnabled(true)` 的安卓守卫(`StartMenu/SelectLayer/NetworkLayer/CreditsLayer`)— 安卓上本就该启用,确认 OK。
- `StartMenu::keyBackClicked` 的 JNI 退出对话框 — 确认 JNI 调用在新包名下能链到。
- **重点**:确认"三页选人 / 默认解锁 / 佩恩大蛇丸复活"这些改动在安卓分支激活后仍生效(这些是平台无关源码改动,理论上不受影响,但要实测)。

### 阶段 5 — 打 APK 并真机运行
- Gradle 打 debug APK → `adb install` → 真机启动。
- **验证门(里程碑)**:游戏在你安卓机上**跑到主菜单并能进一局**。这是路线 A 的成功标志。

## 6. 已知坑与风险

1. **Apple Silicon × 老 NDK**:r10e 是 x86_64 二进制,需 Rosetta 2;个别报告其 `ndk-build` 在新 macOS 上有 make/awk 摩擦。备案:改用 r17c,或在 Win11/Linux 上编 native。
2. **gnustl 限制**:`gnustl_static` 对 C++11 支持有限;若游戏代码用到较新特性可能报错(win32 用 MSVC 编过不代表 gnustl 过)。届时逐个补。
3. **extensions 强依赖 curl**:其 `Android.mk` 默认 `+= cocos_curl_static`;砍网络需改这条或做变体,是阶段 3 的核心风险点。
4. **arm64-v8a 缺位**:路线 A 只出 armeabi-v7a(32 位)。绝大多数安卓机兼容 32 位可运行;极少数纯 64 位新机不行。要 64 位 = 升级到路线 B(另议)。
5. **资源大小写敏感**:安卓/Linux 文件系统大小写敏感,win32 不敏感;`Resources/` 里若有大小写不一致的引用,安卓上会 `Get data from file failed`(参考 win32 缺 XML 崩溃同类问题)。
6. **APK 体积**:含 52M 资源,APK 约 55M+,正常。

---

## 7. 与最终目标(LAN 联机)的衔接

安卓能跑起来后,才进入**真正的初心:无服务器局域网联机**。届时网络层另起方案(UDP 广播发现 + socket 同步),与现在砍掉的 HTTP NetworkLayer 无关。安卓的好处:同一 WiFi 下多台手机联机正是 LAN 对战最自然的形态。
