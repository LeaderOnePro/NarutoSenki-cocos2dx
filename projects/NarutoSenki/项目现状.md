# 火影战记 NarutoSenki — 项目现状地图

> 最后更新:2026-06-13
> 本文记录项目的真实完整度、构建/运行方式、已知问题与各平台移植缺口,作为后续开发的基准参考。
> 结论性事实均经过实际验证(编译、运行、读源码),非推测。推测处会明确标注。

---

## 0. 一句话概括

**这是一个完整、可运行的 cocos2d-x 2.2.6 游戏,但只带了 Windows 一个平台的打包工程。**
游戏本体(代码 + 资源)是完整的;Android / iOS / macOS / Linux 的工程文件都没有。
它是一份**开发者自用的工作副本快照**(停在某次迭代中间),不是对外打磨过的发布版导出——这解释了菜单里的若干"测试态"行为。

## 2. 源码结构速览

类层次(实体系统,基类 `ActionManager`):


## 3. Windows 构建与运行(已验证)

### 工具链真相(⚠️ 与项目内迁移文档不符,以此为准)

迁移文档假设的是 "VS2022 / 工具集 v143 / 路径 ...\2022\Professional",但**本机实际安装的是**:

- **Visual Studio 版本 18(即 VS2026)Professional**
  路径:`E:\Program Files\Microsoft Visual Studio\18\Professional`
- MSVC 工具集只有一个:`14.50.35717`,其 PlatformToolset 名为 **`v145`**
- **`v143` 工具集未安装** → 直接编译会报 `MSB8020: build tools for v143 cannot be found`
- Windows SDK:`E:\Windows Kits\10\`(含 `10.0.26100.0`),`WindowsTargetPlatformVersion=10.0` 自动取最新,无需改
- JDK 17 在 `E:\Program Files\Java\jdk-17`(安卓用,见 §6)

### 编译命令(不改任何 vcxproj,用全局属性覆盖工具集)

```bash
MSBUILD="/e/Program Files/Microsoft Visual Studio/18/Professional/MSBuild/Current/Bin/MSBuild.exe"
cd projects/NarutoSenki/proj.win32
"$MSBUILD" NarutoSenki.sln -p:Configuration=Debug -p:Platform=Win32 -p:PlatformToolset=v145 -m -nologo -v:minimal
```

- 会级联编译全部 6 个项目:chipmunk → Box2D → CocosDenshion → libcocos2d → libExtensions → NarutoSenki
- 首次约 1 分钟,**0 错误**(约 30 个无害警告:无符号比较、未用变量、`/Gm` 弃用等)
- 产物全部输出到 `proj.win32\Debug.win32\`:`NarutoSenki.exe`(~3MB)+ 全部依赖 DLL(libcocos2d/libExtensions/libCocosDenshion/glew32/libcurl/sqlite3/websockets/pthreadVCE2/zlib1 等)

### 运行方式(有坑)

游戏按**当前工作目录(CWD)**加载资源,不是 exe 所在目录。
依据:`cocos2dx/platform/win32/CCFileUtilsWin32.cpp:39` 用的是 `GetCurrentDirectoryW`。

- ✅ 正确:把工作目录设为 `Resources` 文件夹再启动 exe
- ❌ 错误:直接双击 `Debug.win32\NarutoSenki.exe`(找不到资源)
- DLL 与 exe 同在 `Debug.win32`,Windows 从 exe 目录加载,**不受 CWD 影响**

**一键启动器**:已创建 `projects/NarutoSenki/启动游戏.bat`,双击即可(已自动设好工作目录)。
手动启动(PowerShell):
```powershell
Start-Process "...\proj.win32\Debug.win32\NarutoSenki.exe" -WorkingDirectory "...\proj.win32\Resources"
```

启动成功标志:窗口标题 `NarutoSenki - 480x320 - 1.00`。

### Debug vs Release

- `Release.win32` 目录里**没有 exe**(从未成功编出),只有旧日志和一个 DLL
- Debug/Release 是**同一份源码、不同编译选项**(优化、`_DEBUG`/`NDEBUG`、调试/发布 CRT),**游戏行为完全相同**
- 游戏逻辑代码里**没有任何** `_DEBUG`/`NDEBUG` 条件分支(命中的全在第三方 `sqlite3.c` 等)
- 将来发布给他人:编 Release(更快更小)。命令同上,把 `Configuration=Debug` 换成 `Release`

## 4. 已知"测试态"行为(都在源码里,非平台/非 Debug-Release 差异)

这三个现象是开发者留下的调试捷径,**都在共享源码里,所有平台都受影响**,且都可恢复。

### ① PC 上菜单"返回"全部失效

- 框架已把 `ESC`/`F1` 映射为返回事件(`cocos2dx/platform/win32/CCEGLView.cpp:458`)
- 但各界面开启键盘接收的那行被安卓守卫包住了:
  ```cpp
  if(CC_TARGET_PLATFORM == CC_PLATFORM_ANDROID){ this->setKeypadEnabled(true); }
  ```
  共 4 处:`StartMenu.cpp:482`、`SelectLayer.cpp:214`、`NetworkLayer.cpp:413`、`CreditsLayer.cpp:82`
- 结果:PC 上**所有菜单**都收不到返回事件 → ESC/F1 无效
- 修法:去掉这 4 处(及对应 `keyBackClicked` 内的 `setKeypadEnabled(false)`)的安卓守卫。小、安全。

### ② 进不去选人界面,点"训练"直接开打

- `StartMenu.cpp:3380-3383` 的 `SelectLayer::create()` 跳转被 `/* */` 注释掉了
- `SelectLayer` 本身**完整可用**:触摸选角 → 组队 `tempHeros` → `LoadLayer` 进游戏(`SelectLayer.cpp:402-408`),走的正是训练那段同样的进场流程
- 修法:把训练按钮重新接到 `SelectLayer`(约几行)。属中等改动,需确认接线。

### ③ 角色必定是千手纲手(Tsunade)

- `StartMenu::onTrainingCallBack()` 默认走 `i==1` 分支,**写死** `CCString::create("Tsunade")`(`StartMenu.cpp:3427`),对手是固定 5 人 AI
- 只有 `Cheats>10` 才走 `i==2`(全名单**随机** 4v4),但仍不让玩家选
- 修法:随 ② 一起,改为由 `SelectLayer` 决定玩家角色

## 5. 后端依赖与联机现状

- `NetworkLayer`(1070 行)+ `Defines.h` 里 `SERVER "http://localhost/"` + `MemberID`/`GroupID`/排行榜
- 原设计依赖一个 **HTTP 后端服务器**(账号、排行、联机),该服务端**未随源码提供**(正常:客户端源码本就不含服务端)
- 还有 `Cheats` 全局变量、MD5 校验(`CMD5Checksum`,完整性/反作弊)
- **目标方向**:改造成**无服务器的局域网(LAN)联机**。选人界面(§4②)正是联机前选角色的入口,需先恢复。

## 6. 各平台移植缺口 & 补法

| 平台 | 缺什么 | 补法与难点 |
|---|---|---|
| **Android** | `proj.android` + NDK 兼容 | 用 `samples/Cpp/HelloCpp/proj.android` 作模板从零建(`jni/Android.mk` 列全 Classes、`AndroidManifest.xml`、继承 `Cocos2dxActivity` 的 Java 入口、`Resources`→`assets/`)。**最大坑**:框架 `Application.mk` 用 `APP_STL := gnustl_static`,而本机 NDK 是 r26/r27(gnustl 在 r18 已删、仅 clang、最低 API 21)→ 编不过。两条路:① 装回老版 **NDK r10e**(2.2.6 配套,改动最小);② 移植到现代 NDK(改 `c++_static` + 修一堆 libc++/clang 报错,工作量大)。打包还需自写 Gradle(老式 Eclipse+Ant 已废,JDK17 不兼容) |
| **iOS** | `proj.ios` | 需 macOS + Xcode 环境。建 `proj.ios`,`Classes`/`Resources` 复用 |
| **macOS** | `proj.mac` | 同上,需 macOS + Xcode |
| **Linux** | `proj.linux` + Makefile | 需 Linux 环境(框架根有 `make all` 体系可参考) |
| **Windows(Release)** | 仅未编译 | 一条命令(§3,改 `Configuration=Release`) |

> 通用规律:换平台 = 建该平台的 `proj.xxx` 脚手架(游戏 `Classes`/`Resources` 原样复用),**难点在工具链不在游戏代码**。
> 游戏代码里仅有少量平台特化:`StartMenu::keyBackClicked` 的 JNI 退出对话框、`setKeypadEnabled` 安卓守卫——这也佐证**作者当年主力平台是安卓**,Windows 工程偏开发调试用。

## 7. 目标与下一步

**核心目标**:给这款 2016 年停更的游戏加入**局域网联机对战**(无需服务器),用于个人/朋友间的怀旧重温。

建议推进顺序(均在 Windows 上做,迭代快):
1. **修返回键**(§4①)——小而安全,立刻改善 PC 操作
2. **恢复选人界面 + 去掉纲手写死**(§4②③)——让游戏"像个正常游戏",也是联机选角入口
3. **调研并落地局域网联机**(§5)——评估改造 `NetworkLayer` 走 P2P/LAN,还是另起模块
4. (远期)**Android 等平台移植**(§6)——作为发布里程碑,放到玩法/联机跑通之后

Android 不是"正常版"的捷径:它同样有 §4 的测试态行为,只是硬件返回键能用。
